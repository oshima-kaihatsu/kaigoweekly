# KAIGO WEEKLY（非公開の試作、旧名：けあジン）

介護の小規模事業所の経営者・採用担当に向けたメディアの試作。公開・配信はしていない。

## 作り方
1. `articles/*.md` を書く（冒頭の `kind` で種類を決める：topic＝1話題1ページ、weekly＝週次リンク集、guide＝解説、page＝運営者・編集方針）
2. `node build.js` を実行 → `articles/*.html` ができ、`index.html` の一覧が更新される

見た目は `assets/site.css`（トップ・記事ページ共通）。写真は `assets/*.webp`、記事の絵は `assets/spot-*.png`。以前の絵（SVG）は `_design/old-svg/` に退避した。フォントはGoogle Fontsから読み込む。

話題ページの見出しの順番と、事実確認・AIの使い方の決まりは `articles/editorial-policy.md` を参照。

## 公開する前のチェック（経営者の承認が前提）
- [ ] 公開の承認をもらった
- [ ] 全ページの `<meta name="robots" content="noindex, nofollow">` を外した（index.html と article-template.html）
- [ ] 試作の表示（上部の黄色い帯、「試作のため社名は仮」、editorial-policy の試作の注記）を外し、運営者情報を本物にした
- [ ] 編集責任者（人）が、全記事の事実・数字・出典・段階を一次情報で確かめ、確認日と確認者を記録した
- [ ] プライバシーポリシーと、メール配信の同意・配信停止の仕組みを用意した（特定電子メール法：送信者の名前・住所、配信停止の連絡先）
- [ ] 配信停止と再登録を、メール内のリンク→メールアドレス確認で自動処理できるようにした（配信サービスの機能で実現するか、自作するかを決める）
- [ ] ご要望フォーム（UGC）の送信先、保存先、記事での紹介の可否の同意、無料作成の選考条件を決めた
- [ ] 検索とタグの絞り込みが、記事が増えても動くか確かめた（今は一覧をページに埋め込む方式）
- [ ] 記事ごとに幅1200px以上の画像を用意し、構造化データの image に入れた
- [ ] build.js の `SITE_URL` に本番のURLを入れ、週次記事の構造化データのURLが絶対URLになったことを確かめた
- [ ] 求人の無料点検の申込ページを用意した（応募者の個人情報は預からない設計）
- [ ] 記事の日付を、実際の公開日に合わせた（日付をさかのぼらせない）
- [ ] フォントをGoogle Fontsから読むか、自前で配るかを決めた
- [ ] 公開時のアクセス制限と robots の切り替えを確かめた
